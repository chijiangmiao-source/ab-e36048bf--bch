# 窄义二进制 BCH 码字离线复核

一个**零运行时依赖**的静态 Web 工具，用于在受扰链路只能携带硬判决比特的场景下，
由地面工程师**离线**确认一段长度恰为 `2^m−1` 的接收码字，能否按指定的
**窄义二进制本原 BCH 码**规则被纠正——而不是把超出能力的损坏伪装成正常数据。

所有有限域与纠错计算在 **Web Worker** 中完成；Worker 使用的算法库与 Node 测试
是**同一份 ES Module**（`src/lib/`），从根本上保证页面行为与测试一致。

## 复核规则（严格按此判定）

1. **先验证本原多项式**：输入比特串必须恰为 `m` 次、在 GF(2) 上不可约，
   且其根 `α` 的乘法阶恰为 `2^m−1`（Rabin 不可约判据 + 阶因子判据）。
2. **构造生成多项式**：取连续根 `α, α², …, α^(2t)` 所在的互不相同
   **2-循环陪集**，各陪集最小多项式之积即为 `g(x)`；校验其次数满足有效码长。
3. **同一位序**计算：
   - 综合症 `S_j = R(α^j)`，`j=1..2t`（Horner）；
   - Berlekamp–Massey 求错误定位多项式 `σ(x)`；
   - Chien 搜索枚举每个比特位置 `p`，检验 `σ(α^(−p))=0`。
4. **仅当** Chien 找到的根数 **等于** `deg σ`，**且**纠正后重算的
   `S₁…S₂ₜ` **全部为零**，才给出“可纠正”结论。
5. 输入位串非法、参数组合非法、生成多项式次数不满足有效码长、或定位证据
   无法闭合时，页面稳定给出**失败阶段与原因**，并**清除旧成功证据**
   （结果区整块重写，绝不残留上一次的生成多项式/综合症/根）。

### 位序约定（全项目唯一）

比特串第 `i` 个字符（串首为 `i=0`）是多项式 `x^i` 的系数：

```
串:    1  1  0  1
幂:    x⁰ x¹ x² x³      =>  x³ + x + 1
下标:  0  1  2  3
```

生成多项式、接收码字、纠正后码字、Chien 根位置全部使用该位序；页面同时给出
0 起位置 `p`（对应 `x^p`）与 1 起“第几位”。

> 代数边界（如实告知）：当 `t=1` 时任意接收字恒有 `S₂=S₁²`，BM 必产生
> 1 次多项式且在域内恰有 1 根，因此 3 个错误会发生 BCH 固有的**代数误纠**，
> 任何纯代数闭合判据都无法识别。对 `t≥2`，超出能力的图样会通过
> `deg σ>t`、Chien 根数不足或纠后综合症非零被稳定拒绝。本工具严格按
> 题目给定的两条闭合证据判定，不额外宣称能力之外的检测。

## 页面使用

1. 填写域阶数 `m`（2..16）、本原多项式比特串、纠错能力 `t`、长度 `2^m−1` 的码字；
2. 点击 **复核**，查看：生成多项式（及所用陪集）、综合症、错误定位多项式、
   根对应的比特位置、纠正后码字（翻转位高亮）；
3. 点击 **清空草稿和结论** 同时清空输入与所有结论。

内置示例（`x^0` 在串首）：

| m | 本原多项式 | 比特串 |
|---|---|---|
| 3 | x³+x+1 | `1101` |
| 4 | x⁴+x+1 | `11001` |
| 5 | x⁵+x²+1 | `100101` |
| 7 | x⁷+x³+1 | `10010001` |
| 8 | x⁸+x⁴+x³+x²+1 | `101110001` |

## 本地运行（仅需 Node ≥ 18，无需 npm install）

```bash
node scripts/verify.mjs     # 测试 + 构建 + 起服务 + 健康页/可纠正样例 HTTP 冒烟；退出码结束
node scripts/build.mjs      # 仅构建 dist/
PORT=8080 node scripts/serve.mjs   # 起静态服务（dist 不存在时回退 src）
node test/run.js            # 仅跑有限域与纠错规则测试（约 2900 项断言）
```

健康响应：`GET /healthz` → `200 {"status":"ok",...}`。

## Docker Compose

宿主机端口可用 `HOST_PORT` 配置（默认 `8080`）：

```bash
HOST_PORT=9090 docker compose up -d --build web
curl http://localhost:9090/healthz
```

**verify 单次服务**：针对本题运行有限域与纠错规则测试、构建页面，并对健康页
和可纠正样例作 HTTP 冒烟，完成后以退出码结束（适合 CI）：

```bash
docker compose run --rm verify
# 退出码 0 = 全部通过；非 0 = 有失败项
```

## 目录结构

```
src/
  index.html        页面结构
  styles.css        样式
  app.js            主线程：表单 / Worker 通信 / 证据渲染（不含任何域运算）
  worker.js         Web Worker：调用同源 lib 完成全部计算
  lib/gf.js         GF(2^m)：不可约/本原判定、域表、四则运算
  lib/bch.js        陪集、最小多项式、生成多项式、综合症、BM、Chien、闭合判定
scripts/
  build.mjs         构建 dist（原生 ESM，无需打包器）
  serve.mjs         零依赖静态服务 + /healthz + 防路径穿越
  verify.mjs        单次校验服务（测试→构建→起服务→HTTP 冒烟→退出码）
test/
  run.js            有限域与窄义 BCH 规则测试（含确定性错误注入/误纠边界）
```

## 安全与健壮性

- 静态服务对请求路径做规范化校验，拒绝目录穿越；未知路由返回 404 JSON。
- Worker 内对任意异常兜底为结构化失败 `{ok:false,stage,reason}`，页面不会白屏。
- 大参数（最大 `m=16`，码长 65535）下综合症/BM/Chien 均可在 Worker 内离线完成。
